[ ] normally open — passes power when TRUE  ·  [/] normally closed — passes power when FALSE
series contacts are AND · parallel branches are OR · +∥ adds a branch · wires light where power actually flows
green = energized this scan  ·  arithmetic uses function blocks, not operators
an IF/ELSE in text becomes two rungs gated by the same variable and its complement

the diagram is editable: click a tag, pin, or coil to rename it · click a contact symbol to flip [ ]/[/] · drag ⋮⋮ to reorder rungs · drag contacts to reorder them · × deletes · type any expression into a pin
diagram edits regenerate the text in flat rung form — complementary rungs collapse back to IF/ELSE, comments are dropped

this is a real scan: state persists between scans, so seal-in rungs latch and TON/TOF/TP timers, CTU/CTD counters and R_TRIG/F_TRIG edges work — declare instances in VAR … END_VAR, call them like tmr(IN := b, PT := T#5s), read tmr.Q · reset is a cold restart · step single-scans while stopped

how the plant runs
the plant runs on the same scan as the logic: transmitters write their tank's level into their tag before each scan, the logic runs, then valves and pumps move flow and tanks integrate it

valve opens to its tag's value (0–100) · pump runs from a BOOL tag · LT publishes tank level · flows animate where liquid moves · a full tank with net inflow shows overflow

a controller is a device too: select it and press open logic (or double-click it) to edit the program it runs · the Logic view shows which program you are editing — a controller's, or the free-standing sandbox

try the level control plant, watch it settle near SP — then load the sign error logic example and watch the same plant run away · the workspace is saved in this browser and travels as a .llp project file; a .st file carries logic alone
